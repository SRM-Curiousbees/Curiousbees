## 1. Feature-by-Feature Assessment

| X Pattern / Capability | Status | Verified Implementation Details | Research-Platform Relevance (SRM) |
| :--- | :--- | :--- | :--- |
| **Home Timeline** | **Partially Implemented** | `/feed` renders `ResearchPostCard` stream with `Latest` / `Top` sort and type filter pills. However, `GET /api/threads` returns a flat array (`take <= 50`) without `nextCursor`/`hasMore` metadata, and `/feed` has no "Load more" or infinite scroll. | **Essential** — Core daily surface for scholars & supervisors. |
| **For You & Following** | **Partially Implemented (Client-Side)** | `For you`, `Following`, and `Discover` tabs exist in UI, but filtering/scoring runs in browser `useMemo` over only the fetched 20 posts. `Following` silently falls back to global posts when user follows 0 accounts/topics. | **High** — Must move server-side so followed supervisors/scholars are never missed. |
| **Post Composer** | **Fully Implemented** | `CompactComposer` supports title, body, post type, tags, journal metadata, and S3 image/PDF/Word attachments (up to 10 MB with magic-byte checks). | **Essential** — Well-tailored to academic updates & papers. |
| **Post Types** | **Fully Implemented** | 8 `ThreadType` values (`TEXT`, `RESEARCH_UPDATE`, `DISCUSSION`, `QUESTION`, `PUBLICATION`, `ACHIEVEMENT`, `COLLABORATION_REQUEST`, `ANNOUNCEMENT`) with color-coded badges. | **High** — Structured academic intent beats generic tweets. |
| **Likes** | **Fully Implemented** | `ThreadLike` (`@@unique([threadId, userId])`), optimistic UI + in-app notification to author. | **High** — Lightweight peer validation. |
| **Comments & Nested Replies** | **Fully Implemented** | `Comment` self-referential `parentId`, `CommentLike`, recursive `FeedComments` up to depth 3, edit/delete own comments. | **Essential** — Enables scholarly Q&A and peer critique. |
| **Reposts & Quote-Posts** | **Not Implemented** | No repost or quote-post model/UI exists (`ThreadShare` only logs external share clicks). | **High** — Lets supervisors amplify a scholar's paper/update with commentary. |
| **Bookmarks** | **Fully Implemented** | `SavedThread` (`@@unique([threadId, userId])`) + dedicated `Saved` filter pill on `/feed`. | **High** — Crucial for saving papers & reading lists. |
| **Sharing** | **Implemented (External Only)** | `ShareModal` copies `/feed/[id]` link or opens WhatsApp/LinkedIn/Email; `/feed/post/[id]` redirects to `/feed/[id]` (requires login). | **Medium** — Works for institutional sharing. |
| **Following & Followers** | **Partially Implemented** | `UserFollow`, `DomainFollow`, `TopicFollow` work via API & menus, but UI lacks a dedicated Followers/Following list drawer/tab on `/profile` and `/researchers/[id]` (despite `GET /users/:id/followers` & `/following` existing in API). | **High** — Core academic social graph. |
| **Researcher Discovery** | **Fully Implemented** | `/researchers` filters by campus, faculty, department, role, interest, plus alignment score & supervisor capacity; sidebar `Suggested Peers` (`GET /api/feed/peers`). | **Essential** — Key for finding supervisors & co-authors. |
| **Search** | **Partially Implemented** | `GET /api/feed/search` searches threads, publications, and users; `⌘K` `SpotlightSearch` only searches **already-loaded client store items** unless clicking "Search all posts". | **High** — Global search should query backend directly. |
| **Hashtags & `@mentions`** | **Partially Implemented (Tags only)** | `tags: String[]` works as separate chips and trending topics, but **no inline `#hashtag` parsing** and **no `@mentions`** (autocomplete, linking, or notifications) exist. | **High** — `@mentions` are vital for tagging supervisors/co-authors in updates & replies. |
| **Notifications** | **Partially Implemented** | Persisted `Notification` DB table + bell dropdown + `/notifications` page. No live polling/SSE; `sendPushToUser` is disabled on backend while `PushNotificationPrompt` emits **mock** browser alerts when tab is hidden. | **High** — Real notification delivery needed for replies, mentions, and supervision. |
| **Direct Messaging** | **Implemented (Collaboration-Gated)** | `CuriousNexusHub` (`/nexus`) requires a `ResearchCollabRequest` -> accept -> `ResearchCollaboration` + `CollaborationMessage` (no instant open DM, no live polling). | **Medium-High** — Intentional academic friction prevents spam, though live message refresh is missing. |
| **User Profiles** | **Fully Implemented** | `AcademicProfileView` shows bio, role, department, supervisor/scholars, publications, research lifecycle, and external links (`ORCID`, `Google Scholar`, `GitHub`, etc.). Missing: a "Posts" tab showing the researcher's own feed threads. | **High** — Adding a researcher's post history on their profile completes the X pattern. |
| **Trending Topics** | **Fully Implemented** | `FeedService.getTrendingResearch` weights tags by likes/comments/shares + `ResearchInterest` user counts, rendered in `ResearchDiscoverySidebar`. | **Medium** — Good academic discovery signal. |
| **Mobile Experience** | **Partially Implemented** | Responsive sidebar drawer + `MobileFeedNav` bottom bar on `/feed` only; `/nexus`, `/researchers`, and `/notifications` lack the mobile bottom bar. | **High** — Consistent mobile nav across social routes improves daily engagement. |
